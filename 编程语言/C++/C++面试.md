#### （0） 指针和引用的区别 (重要)

- 指针是保存地址的对象，可以为空、可以重新指向，也可以有多级指针。引用是已有对象的别名，声明时必须绑定，之后不能改绑。
- 使用指针要显式解引用，引用的语法和原对象一样。两者都可能悬垂，所以都不能超过目标对象的生命周期。

#### （1）在函数参数传递的时候，什么时候使用指针，什么时候使用引用？ (重要)

- 函数参数传递时，如果<mark style="background:#fff88f">参数一定存在、不能为 `nullptr`</mark>，通常优先使用引用；如果<mark style="background:#fff88f">参数是可选的，允许没有对象</mark>，则使用指针，因为指针可以用 `nullptr` 表达“没有”。

- 如果只是读取对象，可以用 `const T&`；如果需要修改调用者对象，可以用 `T&`。如果参数涉及所有权转移，则一般不用裸指针或普通引用，而使用 `std::unique_ptr`、`std::shared_ptr` 等智能指针明确所有权语义。

#### （2） 堆和栈有什么区别 (重要)

- 栈上的存储通常由编译器和运行时自动管理，函数调用时建立栈帧，离开作用域时自动回收，分配释放通常很快；
- 堆上的内存需要动态申请，C++ 中通常通过 `new`、`malloc` 或分配器获取，生命周期由程序显式控制或通过 RAII 管理。

- 栈空间通常较小，适合局部变量和短生命周期对象；
- 堆空间通常更大，适合大小运行时才能确定、生命周期跨越当前作用域或者体积较大的对象。堆分配还可能带来分配器开销、碎片以及较差的局部性。

#### （3）堆快一点还是栈快一点？（字节提前批一面）

- 通常栈上分配更快，因为分配和回收往往只需要移动栈指针。堆分配要查找合适的空闲块，还要处理元数据、并发和碎片。
- 但这只是一般规律，实际性能还取决于分配器、对象大小、缓存局部性和编译器优化。对象一旦分配完成，访问速度主要看内存局部性，不能说堆对象每次访问都一定更慢。

#### （4） `new/delete` 如何实现、与 `malloc/free` 有何区别，C++ 为什么仍需要它们？ (重要)

- `new` 表达式做两件事：先调用 `operator new` 取得原始存储，再在这块存储上构造对象。
- `delete` 的顺序相反，先析构，再调用 `operator delete` 释放存储。
- `malloc/free` 只按字节管理原始内存，不调用构造和析构；`malloc` 失败返回空指针，普通 `new` 失败默认抛出 `std::bad_alloc`。
- 三组接口必须分别配对：`new/delete`、`new[]/delete[]`、`malloc/free`，不能混用。工程代码一般优先用容器、`make_unique` 或 `make_shared`。

#### （7）delete 和 delete\[\]的区别 (重要)

- `delete` 用来释放通过 `new T` 创建的单个对象，`delete[]` 用来释放通过 `new T[n]` 创建的数组。  
- 对于类类型，`delete` 会调用一次析构函数，而 `delete[]` 会<mark style="background:#fff88f">对数组中的每个元素依次调用析构函数，然后释放整块内存</mark>。

#### （10） Struct 和 class 的区别 (重要)

- 在 C++ 里，`struct` 和 `class` 的能力基本相同，都能有成员函数、构造析构、继承、虚函数和模板。
- 语言层面的主要区别只有两个：`struct` 的成员和继承默认是 `public`，`class` 默认是 `private`。
- 工程习惯上，我用 `struct` 表示以数据为主、约束较少的聚合，用 `class` 表示需要维护不变量和封装实现的类型，但这只是风格约定。

#### （11） `#define` 和 `const` 的联系与区别（编译阶段、安全性、内存占用等） (重要)

- `#define` 是预处理阶段的文本替换，没有类型、作用域和正常的调试信息。`const` 声明的是受类型系统和作用域约束的对象。
- 宏参数还可能因为重复求值和运算符优先级出错，所以常量优先用 `constexpr` 或 `const`，函数式宏优先用内联函数或模板。
- 至于是否真正占内存，要看对象是否被使用、是否取地址以及编译器优化，不能简单说宏不占而 `const` 一定占。

#### （12） 在 C\+\+中 const 的用法（定义，用途） (重要)

- `const` 表示不能通过当前接口修改对象。它可以修饰变量、指针指向的对象、指针本身、函数参数、返回值和成员函数。
- `const T*` 是指向常量的指针，`T* const` 是不能改指向的常量指针。`const` 成员函数不能修改普通成员，也不能直接调用非 `const` 成员函数。
- 若原对象本身就是 `const`，去掉限定后再修改属于未定义行为。`mutable` 只适合缓存或统计等逻辑上不改变对象状态的成员。

#### （13） C++中的 static 用法和意义 (重要)

- 函数内的局部静态变量具有<mark style="background:#fff88f">静态存储期</mark>，只在第一次执行到声明时初始化，C++11 起这个初始化是线程安全的。
- 命名空间作用域的 `static` 变量或函数具有<mark style="background:#fff88f">内部链接</mark>，只在当前翻译单元可见。
- 类的静态数据成员由所有对象共享，静态成员函数没有 `this` 指针，只能直接访问静态成员。
- 简单说，`static` 主要改变存储期、链接属性或把成员提升到类级别。


#### （15） C++的 STL 介绍，其中包括内存管理 allocator，函数，实现机理，多线程实现等 (重要)

- STL 是 C++ 标准库中基于泛型编程的一套组件，主要包括<mark style="background:#fff88f">容器、迭代器、算法、函数对象和 allocator</mark>。
- 容器负责存数据，比如 vector、map；
- 迭代器统一访问容器；
- 算法负责排序、查找等操作；
- 函数对象和 Lambda 用来定制比较规则。
- allocator 负责的是原始内存的申请和释放
- 它们通过模板解耦，算法通常依赖迭代器能力，而不依赖具体容器。

#### （18） STL 中 unordered_map 和 map 的区别 (重要)

- `map` 按键有序，查找、插入和删除是 O(log n)，主流实现是平衡树，适合顺序遍历、范围查询和稳定最坏复杂度。
- `unordered_map` 按哈希分桶，平均 O(1)、最坏 O(n)，不保证按键顺序，适合精确查找。


#### （19） STL 中 vector 的实现 (重要)

- `vector` 本质是连续存储的动态数组，通常维护首地址、元素个数和容量。容量足够时尾插直接在末尾构造。
- 容量不足时申请更大的连续空间，把旧元素移动或复制过去，再释放旧空间。扩容倍数由实现决定，不保证是两倍。
- 它支持 O(1) 随机访问，尾插均摊 O(1)，中间插删通常 O(n)。重新分配会使原来的指针、引用和迭代器失效。

#### （20） vector 使用的注意点及其原因，频繁对 vector 调用 push_back\(\)对性能的影响和原因 (重要)

- 频繁 `push_back` 本身不一定有问题，因为它是均摊 O(1)。真正的开销来自容量不足时的重新分配、元素搬迁和迭代器失效。
- 如果提前知道数量，我会用 `reserve` 预留容量，注意 `reserve` 只改容量，`resize` 会改变元素个数并构造对象。
- 另外不要保存可能因扩容失效的地址。是否换成 `list` 要看访问模式，不能只因为尾插多就换，因为 `vector` 的局部性通常更好。


#### （21）C++中 vector 和 list 的区别 (重要)

- `vector` 连续存储，随机访问 O(1)，缓存局部性好，尾插均摊 O(1)，但中间插删要移动元素，扩容会使迭代器失效。
- `list` 是双向链表，不支持随机访问。如果已经拿到位置，插删是 O(1)，而且其他元素的迭代器通常不受影响，但每个节点有额外指针和独立分配，局部性较差。
- 工程上我默认先考虑 `vector`，只有确实需要稳定节点地址和大量已定位位置的插删时才考虑 `list`。

#### （22） C++中的重载和重写的区别 (重要)

- 重载发生在同一作用域，函数名相同但参数列表不同，编译器在编译期选择。仅返回类型不同不能构成重载。
- 重写发生在继承体系中，派生类为基类虚函数提供兼容实现，运行时通过动态绑定选择。
- 实际编码应写 `override`，让编译器检查签名。还要区分隐藏：派生类声明同名函数可能把基类的同名重载都隐藏掉，但这不等于重写。


#### （23） C ++内存管理 (重要)

从程序运行角度看，进程虚拟地址空间通常包括<mark style="background:#fff88f">代码段、只读数据段、数据段、BSS、堆、mmap 区域和线程栈</mark>。函数局部对象通常具有自动存储期，随作用域自动销毁；全局变量和静态变量具有静态存储期；`new` 创建的对象具有动态存储期，需要显式释放或者交给 RAII 对象管理。

#### （24） 面向对象的三大特性，以及 C++ 多态如何实现 (重要)

- 三大特性是封装、继承和多态。封装通过访问控制和稳定接口隐藏实现并维护不变量。继承表达“is-a”关系并复用接口或实现。多态让同一个接口对应不同实现。
- C++ 的编译期多态主要有重载和模板，运行时多态主要靠虚函数：通过基类指针或引用调用时，根据对象的动态类型选择最终重写函数。
- 主流 ABI 用虚表和虚指针实现，但标准只规定行为，不规定具体布局。

#### （26） C++虚函数相关（虚函数表，虚函数指针），虚函数的实现原理 (重要)

- C++ 的虚函数主要用于运行时多态。只要类中存在虚函数，主流编译器通常会为这个<mark style="background:#fff88f">类</mark>生成一张虚函数表，表中保存该类各个虚函数最终实现的函数地址。

- <mark style="background:#fff88f">对象</mark>中通常会额外保存一个隐藏的虚函数指针 vptr，指向当前对象对应类型的虚函数表。

- 当通过基类指针或引用调用虚函数时，编译器不能在编译期直接确定调用哪个函数，而是在运行时通过对象的 vptr 找到 vtable，再从固定槽位取出函数地址并进行间接调用，从而实现动态绑定。

- <mark style="background:#fff88f">如果派生类重写了基类虚函数，派生类的虚函数表中对应位置会替换成派生类函数的地址</mark>；没有重写的虚函数则继续指向基类实现。

#### （28）基类的析构函数一般写成虚函数的原因 (重要)

- 如果通过 `Base*` 删除一个实际类型为 `Derived` 的对象，而 `Base` 的析构函数不是虚函数，那么这个 `delete` 的行为是未定义的，派生类析构函数可能不会被正确调用，进而造成资源泄漏。

- 把基类析构函数声明为 `virtual` 后，`delete base_ptr` 会根据对象的动态类型先调用 `Derived::~Derived()`，再调用 `Base::~Base()`，保证整个对象被完整析构。


#### （29） 构造函数为什么不能定义为虚函数 (重要)

因为虚函数的<mark style="background:#fff88f">动态绑定需要依赖对象的虚表指针和运行时类型</mark>，而构造函数执行时对象还没有构造完成，派生类部分可能还不存在，无法完成正确的动态分派。所以 C++ 不允许构造函数声明为虚函数。


#### （30） 构造函数或者析构函数中调用虚函数会怎样 (重要)

- 在构造函数或析构函数中调用虚函数时，**不会发生向派生类的动态绑定**；调用的是当前正在构造或析构的那个类自己的版本。
- 原因是构造时顺序为“先基类、后派生类”，执行基类构造函数时，派生类部分还未初始化；析构时顺序相反，执行基类析构函数时，派生类部分已经销毁。为了<mark style="background:#fff88f">避免访问未初始化或已销毁的派生类成员</mark>，C++ 会把对象视为当前构造或析构的类。

#### （31） 纯虚函数 (重要)

- 纯虚函数用 `virtual f() = 0` 声明，它表达接口契约，并<mark style="background:#fff88f">使类成为抽象类</mark>，<mark style="background:#fff88f">抽象类不能直接实例化</mark>。
- 派生类只有<mark style="background:#fff88f">为所有纯虚函数提供最终重写</mark>后，才是可实例化的具体类。纯虚函数可以有定义，派生类也能显式调用基类版本。
- <mark style="background:#fff88f"> 纯虚析构函数必须提供定义</mark>，因为销毁派生对象时仍会执行基类析构。

#### （33） 深拷贝和浅拷贝的区别（举例说明深拷贝的安全性） (重要)

- 浅拷贝复制的是资源地址，多个对象可能共享同一资源；
- 深拷贝复制的是资源内容，每个对象拥有独立资源。
- C++ 默认拷贝构造和赋值是成员逐个复制，因此包含裸指针并拥有资源的类，如果不自定义拷贝行为，往往会产生浅拷贝问题。现代 C++ 更推荐用 `std::vector`、`std::string`、`std::unique_ptr` 等 RAII 类型管理资源，遵循零法则或五法则。


#### （35） 常见构造函数，以及何时调用拷贝/移动构造函数 (重要)

- 常见构造方式有**默认构造、带参构造、拷贝构造和移动构造，另外还有委托构造和转换构造**。
- 用左值初始化新对象时通常选拷贝构造，用右值或 `std::move` 后的将亡值初始化时优先选移动构造。


#### （37） 结构体内存对齐方式和为什么要进行内存对齐？ (重要)

结构体内存对齐是编译器为成员插入 padding，使每个成员地址满足自身对齐要求的机制。它能提高或保证 CPU 访问效率，并保证数组中的每个结构体元素都合法对齐。结构体大小通常是最大对齐值的整数倍，成员顺序会直接影响空间占用。


#### （38） 内存泄露的定义，如何检测与避免？ (重要)

- 内存泄漏是<mark style="background:#fff88f">程序失去了对已分配内存的有效所有权</mark>，导致它在需要时无法释放。
- 常见原因有**异常路径漏释放、容器长期增长、`shared_ptr` 环、回调生命周期错误和库接口配对错误**。工程上先用 RAII、容器和智能指针预防。
- 测试中用 ASan、LSan 或 Valgrind，线上结合 RSS、堆剖析和分配栈定位。还要区分真正泄漏、分配器缓存和页缓存，不能只看 RSS 上涨就下结论。


#### （39） C++的智能指针有哪些 (重要)

- 标准智能指针主要有 `unique_ptr`、`shared_ptr` 和 `weak_ptr`。
- `unique_ptr` 表示独占所有权，只能移动，是默认首选。
- `shared_ptr` 通过控制块共享所有权，最后一个强引用消失时销毁对象。
- `weak_ptr` 不拥有对象，用来观察共享对象并打破引用环。选择的核心是所有权语义，不是“哪个更安全”。
- 一般用 `make_unique` 或 `make_shared` 创建，并避免从同一个裸指针构造多个独立的 `shared_ptr`。

#### （41） 遇到 coredump 要怎么调试 (重要)

- 遇到 core dump，我先保存与现场完全匹配的可执行文件、动态库、调试符号和 core，再确认崩溃信号与运行参数。
- 用 GDB 加载程序和 core，先看 `bt` 和所有线程栈，再定位崩溃线程的寄存器、源码行和关键对象。若栈损坏，就结合反汇编和地址映射。
- 还要检查 core 是否因 `ulimit`、systemd-coredump 或 `core_pattern` 没有生成。
- 结论必须结合日志、监控和复现验证，不能只修最顶层崩溃行。
