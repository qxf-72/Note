## MySQL 客户端/服务端架构

- **服务器程序**：直接和存储的数据打交道。服务器进程被称为 **MySQL 数据库实例**，进程的默认名称为 **mysqld**。

- **客户端程序**：进程默认名称为 **mysql**。

## 启动 MySQL 服务器程序

### 在 UNIX 中启动

安装目录的 bin 目录之下有多个可执行文件：
-  **mysqld**：直接启动一个服务器进程，命令不常用。
- **mysqld_safe**：启动脚本，间接调用 **mysqld**。另外启动一个**监控进程**，在服务器进程崩溃时，进行重启；将服务器程序出错信息和其他诊断信息重定向到某个文件中，产生**出错日志**。
- **mysql. server**：启动脚本，间接调用 **mysqld_safe**。该文件为一个链接文件。

```bash
mysql.server start    # 启动服务器程序
mysql.server stop    # 关闭服务器程序
```

- **mysql_multi**：用于多个服务器进程的启动、停止和监控。


### 在 Windows 中启动

**手动启动**：在命令行中或鼠标双击运行 mysqld 程序。

**以服务方式运行**

- Windows 服务：如果某个程序需要长时间运行，并且开机自启动，可以将程序注册为 Windows 服务，让操作系统进行管理。

- 注册服务
```bash
"可执行文件完整路径名字"  --install  -manual  [服务的名字] 
```

- 启动或关闭服务
```bash
net start mysql
net stop mysql
```

## 启动 MySQL 客户端程序

```bash
mysql -h主机名字 -u用户名字 -p密码
```

- `-h`：或 `--host=主机名`，服务器进程所在计算机的域名或者 ip 地址。服务器进程在本机运行可以省略该参数，或者填 `localhost` 或 `127.0.0.1`。
- `-u`：或 `--user=用户名`。
- `-p`：或 `--password=密码`。

> - 只有一个英文字母的短形式参数，使用时前面加单短划线；大于一个英文字母的长参数，前面加双短划线。
> - **`-p` 和密码值之间不能有空白字符**，其他参数和值之间可以有。

# 事务与 ACID

## ACID

### 原子性 Atomicity

要么操作成功，如果执行操作过程中发生错误，把已经做了的操作恢复成没执行之前的样子。

### 一致性 Consistency

数据库中的一致性指的是库中数据符合现实世界中的约束。例如银行数据库中账户之间进行交易，账户的支出=账户的收入。还有整个系统的余额=所有账户的收入-所有账户的支出。

数据库中某些操作的原子性和隔离性都是保证一致性的一种手段，在操作执行完成之后保证符合宿友既定约束则是一种结果。但是满足原子性和隔离性，不保证一定满足一致性。

### 隔离性 Isolation

对于现实世界中的状态转换对应的某些数据库来说，不仅仅需要保证 操作以原子性的方式执行完成，还需要保证**其他状态转换不会影响到本次状态转换**。

### 持久性 Durability

数据操作所修改的数据都应该在磁盘中保留下来。

## 事务

事务的英文是 transaction，英文直译就是交易的意思，交易就是买的人付钱，卖的人交货，不能付了钱不交货，交了货不付钱，所以交易本身就是一种不可分割的操作。

事务是一个抽象的概念，对应着一个或者多个数据库操作。按照这些操作所执行的不同阶段，可以分为：

- 活动的：正在执行过程中。
- 部分提交的：操作完成，但是操作结果还没有刷新到磁盘中。
- 失败的：事务在活动或者部分提交时，遇到了某些错误，或者认为中止事务执行。
- 中止的：事务失败之后，回滚到执行事务之前的状态。
- 提交的：部分提交的事务成功刷新到磁盘上面。


### 事务并发执行的问题

- 脏写：一个事务修改了另一个未提交事务修改过的数据。
- 脏读：果一个事务读到了另一个未提交事务修改过的数据。
- 不可重复读：一个事务只能读到另一个已经提交的事务修改过的数据，并且其他事务每对该数据进行一次修改并提交后，该事务都能查询得到最新值。
- 幻读：一个事务两次根据相同条件查询出的结果不一样——一个事务先根据某些条件查询出一些记录，之后另一个事务又向表中插入了符合这些条件的记录，原先的事务再次按照该条件查询时，能把另一个事务插入的记录也读出来。


### 隔离级别

以上问题按照严重性排序：

```
脏写 > 脏读 > 不可重复读 > 幻读
```

使用数据库需要在隔离性和性能之间做平衡：隔离级别越低，越严重的问题就越可能发生。

SQL 标准设立了 4 个隔离级别：
- `READ UNCOMMITTED`：未提交读。
- `READ COMMITTED`：已提交读。
- `REPEATABLE READ`：可重复读。
- `SERIALIZABLE`：可串行化。
